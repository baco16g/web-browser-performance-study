# 0002 読み込みごとの中央値を集計の単位にする

> この文書の解説と考察は、Claude（Anthropic の AI）が実測の結果をもとに書いたものです。

## 状況

1回の読み込みの中で操作を繰り返すと、計測の件数は増やせる。ただし同じ読み込みの中の値は、JIT の状態やメモリの配置を共有していて、独立した観測とは言えない。

## 決定

読み込みごとに中央値を求め、それを1件として中央値と四分位範囲を集計する。生の値は結果の JSON に残す。

## 理由

外れ値に引きずられにくく、読み込みの間のばらつきをそのまま残せる。実行回数を増やすほど値の信頼性が上がる、という関係も分かりやすい。

## 選ばなかった案

- **すべての操作を1つの集団として集計する:** 件数は多く見えるが、四分位範囲を小さく見積もる。
- **平均を使う:** 性能の値は偏った分布になりやすく、まれな遅い値に引きずられる。

## 制約

既定の読み込み回数は 5 回で、p95 を安定して見積もるには足りない。結果の p95 は参考値として扱い、判定には使わない。
