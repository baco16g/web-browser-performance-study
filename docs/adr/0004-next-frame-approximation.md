# 0004 入力から次フレームまでを requestAnimationFrame と MessageChannel で近似する

## 状況

入力への応答を測る標準の手段は Event Timing だが、古いブラウザでは使えない。自動計測では、操作の完了を検知する合図も必要になる。

## 決定

`requestAnimationFrame` の中で `MessageChannel` にメッセージを送り、そのタスクの実行時刻を終点にする。始点は入力イベントの `timeStamp` にする。Event Timing は使える環境で別の指標として併記する。

## 理由

`requestAnimationFrame` は描画の直前に呼ばれるので、そこで積んだタスクは描画の後に実行される。`MessageChannel` は `setTimeout` のように遅延が丸められない。標準の API だけで動くので、対応の幅が広い。

UC2 の結果では、この値とタスクの合計時間がほぼ一致した（`good` で 46.9ms と 46.8ms）。

## 選ばなかった案

- **Event Timing だけを使う:** ブラウザが測る正確な値だが、対応環境に限られ、16ms 未満の値は取れない。
- **`setTimeout(0)` で次のタスクを待つ:** 書き方は簡単だが、遅延の丸めが計測値に混ざる。

## 制約

メインスレッドの仕事の終わりまでを測る近似で、ラスタライズ、合成、表示装置の遅延は含まない。画面に光が出るまでの時間を測るには、外部のカメラなどが必要になる。
