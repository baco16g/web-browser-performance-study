# 0005 実装は改善を1段階ずつ足して比較する

> この文書の解説と考察は、Claude（Anthropic の AI）が実測の結果をもとに書いたものです。

## 状況

遅い実装と速い実装の2つだけを比べると、どの改善がどれだけ効いたのか分からない。律速点を1つ直すと次の律速点が見える、という性能分析の流れも再現できない。

## 決定

UC1、UC4、UC5 では、実装を1段階ずつ改善を足した並びにする。隣り合う実装の差は改善1つだけにする。UC4 と UC5 では、その性質を単体テストで固定する。

## 理由

隣り合う実装の差を読めば、その改善の効果が分かる。UC4 では、取得開始を早めても LCP が縮まず、次の律速点が描画の遅れだと分かった。2つの比較では見えなかった結果である。

## 選ばなかった案

- **改善ごとに独立して切り替える:** 組み合わせは自由になるが、数が増えて全部を測れない。実際の改善も順番に進むので、順番を固定した。
- **遅い実装と速い実装の2つだけにする:** 実装は単純だが、学べることが減る。

## 制約

順番が結果に影響する。ある改善の効果は、それより前の改善が入った状態での値である。別の順番で足せば、同じ改善でも効果の大きさは変わる。
